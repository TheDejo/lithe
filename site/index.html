The problem

Agents are code. We test them like demos.

The usual tools score a single prompt's output. Agents call tools, loop, and make decisions, and that's where they break.

01

Outputs change every run

Exact-match assertions are flaky, so teams stop writing tests at all.

02

Regressions are silent

A prompt tweak makes the agent take a different path. The answer still looks fine, until it doesn't.

03

Failures don't explain themselves

You see the last line that broke, not the five steps that led there. Debugging means re-running and guessing.

Features

Everything you expect from a test runner, plus what agents need.

If you've used Jest or Vitest, you already know how to use Lithe.

Code-first, zero config

describe, test, expect and hooks. TypeScript and ESM work out of the box, with no build step.

Mock models and tools

fn() and spyOn() stub the real Anthropic and OpenAI SDK clients, so tool-calling flows are deterministic in CI.

Assert on meaning

toContainAll, toBeJSON(shape), expect.oneOf and expect.satisfies handle output that varies between runs.

Retries and timeouts

Per-test retries absorb rate limits and flaky model calls, and retried tests are flagged so flakiness stays visible.

Step-by-step traces

Every LLM call, tool call and note() is recorded per test, and printed right under the error when a test fails.

Diff behaviour across commits

lithe compare shows which tests changed between runs, and the first step where each agent diverged.

How it looks

Write a test. Get a clear answer.

Stub the SDK client your agent already uses, script the model's replies, and assert on what the agent does.

tests/support.test.tsTest
import Anthropic from "@anthropic-ai/sdk";
import { test, expect, spyOn } from "@thedejo/lithe";

const client = new Anthropic({ apiKey: "test" });
const create = spyOn(client.messages, "create");

test("looks up the order first", async () => {
  create
    .mockResolvedValueOnce(toolUse("get_order"))
    .mockResolvedValueOnce(text("It ships Friday."));

  const answer = await supportAgent(client, "Where's A-1042?");

  expect(create).toHaveBeenCalledTimes(2);
  expect(answer).toContainAll(["ships", "friday"]);
});

Traces & run records

Know why an agent changed, not just that it did.

Every run can leave a record that another developer, or another agent, can read later.

  1. 1

    Record the steps

    Name a mock, wrap a client with traced(), or call note() to log a decision and its reason.

  2. 2

    Save the run

    lithe --report run.json stores every result and trace, plus the git commit and CI run it came from.

  3. 3

    Compare two runs

    lithe compare lists what broke, what got fixed, and tests that still pass but now behave differently.

CI/CD

Gate every pull request.

Lithe exits non-zero when a test fails, so it works in any CI. Save a run record on every build and compare pull requests against main.

.github/workflows/test.ymlGitHub Actions
- run: npm ci

- name: Run Lithe tests
  run: npx lithe --report lithe-report.json

- name: Save run record
  if: always()
  uses: actions/upload-artifact@v4
  with:
    name: lithe-report
    path: lithe-report.json
anywhere elseAny CI
# GitLab, CircleCI, Azure, Jenkins, Buildkite…
npm ci && npx lithe

# real-model tests: more time, retry flaky calls
npx lithe tests/e2e --timeout 60000 --retries 2

# see what changed versus main
npx lithe compare main.json branch.json
